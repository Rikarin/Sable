# S3107: arguments to @test or @bench

`@bench` takes nothing, or `arguments: [...]` and `tags: [...]`, as `@test` has
them. `@fuzz` takes nothing, or `mutator: f`, the name of a function of the
module, `f(_ input: U8[:], _ seed: U64) -> U8[>..]`, that makes another input
of one. `@test` takes nothing, or: `arguments: [...]`, the
values the test is run with, an array for all its parameters or one for each;
`tags: ["fast"]`, plain strings with no space in them nor what a filter is
written with; `timeout: .seconds(5)`, a literal in `.milliseconds`, `.seconds`
or `.minutes`; and one saying the test must trap. `@test(traps)` passes when the test traps — an index out of range, an
overflow, a `fatal` — and fails when it returns; `@test(traps: "out of
range")` also wants the trap's message to contain that text, written as a
plain string. A failed assertion is not the trap: it fails the test.

To pick which tests run, pass a filter on the command line: `sable test
sorts` runs the tests whose names contain `sorts`, `--filter tag:slow` those
tagged so.

## Example

```sable
module Example

import Sable.Testing

@test("slow")
fn sorts() {
    assert(true)
}
```

## Fix

Say what the argument is.

```sable
module Example

import Sable.Testing

@test(tags: ["slow"])
fn sorts() {
    assert(true)
}
```
