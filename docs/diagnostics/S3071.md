# S3071: `@derive` on a type it does not fit

`@derive` is for structs and unions, whose values are their fields, and for
enums, whose values are their cases. A class or actor object has identity,
so equality and hashing made from its fields would call two distinct objects
equal; write `==` and `hash(into:)` for it instead. A `@flags` enum's values are
sets of its cases, compared as the integers they are, so it derives
nothing. The same code is reported when the type already declares the
member `@derive` would make (an `==` of its own, say), since there would
then be two.

It is also reported for an `@serialize` option that does not fit what it is
written on (docs/06 §6.5): a `tag:` or `untagged` on a type that is not a
union, `untagged` with a `tag:`, a second untagged case that carries nothing,
`flatten` on a field that is not written as a struct or a map, with a `rename:`,
`skip` or `defaulted`, or whose members repeat a key of the struct's, or an
option there is not.

`@derive(Injectable)` (Sable.DependencyInjection) is for what an initialiser
makes: a class, an actor or a struct. It is this error on any other type; on
one with several initialisers of which none, or more than one, is marked
`@Inject`; and for an initialiser that is async, that is generic over type
parameters of its own, or that has a parameter no container gives: an `inout`
or variadic one, a function that takes something, throws or waits, a slice,
or one whose `@Keyed` key is not a string literal.

## Example

```sable
module Example

@derive(Equatable)
class Account {
    var id: Int

    init(id: Int) {
        self.id = id
    }
}
```

## Fix

Make it a struct if its values are just their fields, or write the
conformance by hand.

```sable
module Example

@derive(Equatable)
struct Account {
    var id: Int
}
```
