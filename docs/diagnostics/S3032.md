# S3032: a throwing call without `try`

A call to a function that can throw must be marked with `try` (to pass the
error on), `try?` (to turn it into an optional) or `try ... catch` (to supply
a fallback). The mark keeps every point where control can leave early
visible in the source.

A `for` loop over a sequence whose `Failure` is not Never calls a throwing
`next()` for each element, so it is written `for try` (`for try await` for an
async sequence); generic code over `S: Sequence` either lets the error out,
`throws(S.Failure)`, or asks for a sequence that cannot fail,
`where S.Failure == Never`.

## Example

```sable
module Example

union ParseError { Empty }

fn parse(_ s: String) throws(ParseError) -> Int { return 0 }

fn read() throws(ParseError) -> Int {
    return parse("1")
}
```

## Fix

```sable
module Example

union ParseError { Empty }

fn parse(_ s: String) throws(ParseError) -> Int { return 0 }

fn read() throws(ParseError) -> Int {
    return try parse("1")
}
```
