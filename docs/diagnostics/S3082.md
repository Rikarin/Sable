# S3082: a `@builtin` written wrongly

`@builtin("name")` takes exactly one argument: the builtin's name, as a
non-empty string literal, with no label. Anything else (no argument, two, a
label, an expression that is not a literal) cannot name a builtin.

Only the standard library (`Sable.Core` and the `Sable.*` modules) may
declare a builtin, and anywhere else S3081 is reported first, so this is met
only while working on the library. Write the
name the compiler's table gives the builtin: `@builtin("string_trimmed")`.

## Builtin families

A builtin named with a `Self` segment, `@builtin("count_leading_zeros_Self")`,
is a family: one builtin per type, the segment filled with the type Self
stands for where the member is used. It is declared in a protocol's
extension, as the default the built-in types take for one of the protocol's
requirements, and a builtin in a protocol's extension must be one — nothing
else would say whose builtin it is. Either written elsewhere is this error.

```sable
module Sable.Core

public protocol Counted {
    var bits: Int { get }
}

extension Counted {
    @builtin("count_ones_Self")
    public var bits: Int { get }
}
```
