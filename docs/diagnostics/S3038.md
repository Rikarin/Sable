# S3038: an expression too complex to type-check

The type checker spends a fixed budget on each statement: it binds at most
ten thousand expressions before it gives up and reports this error, naming
the expression it was working on. The limit keeps compile times predictable;
without it, an unlucky expression could take unbounded time to check. Only
very large expressions reach it, such as an array literal with thousands of
nested elements, typically in generated code.

Split the expression into several statements, binding the parts to local
names, and give those bindings type annotations so less has to be inferred
in one piece. Data that large is often better read from a file at run time.
