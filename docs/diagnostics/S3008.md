# S3008: an ambiguous reference to an overloaded function

More than one overload fits equally well and the compiler has no rule to
prefer one. This happens most often when an overloaded function is named
without being called, so there are no arguments to choose by.

## Example

```sable
module Example

fn show(_ n: Int) -> String { return "\(n)" }
fn show(_ s: String) -> String { return s }

fn pick() -> String {
    let f = show
    return f(1)
}
```

## Fix

Give the binding a function type so only one overload fits.

```sable
module Example

fn show(_ n: Int) -> String { return "\(n)" }
fn show(_ s: String) -> String { return s }

fn pick() -> String {
    let f: (Int) -> String = show
    return f(1)
}
```
