# S3161: a requirement about `Self` called through `any P`

An `any P` holds a value of some type that conforms to `P`, and which type is
known only when the program runs. A requirement whose parameters or result
mention `Self`, or one of `P`'s associated types, is about one particular
conformer: `fn same(_ other: Self) -> Bool` compares two values of the same
type, and through two existentials those might be two different types. Such
a requirement cannot be called through `any P`. Call it through a generic
parameter instead, which names one conforming type for the whole call.

A requirement that only gives `Self` or an associated type back is callable:
the existential is opened for the call and the result erased again
(`shape.doubled()` is an `any Shape`; S3165 says when an associated type
cannot be). An optional of one or an
array of them is too. What stays out of reach is a parameter that mentions
one, a result made of one in another way (`(Self, Int)`), a property of `Self`
that can be set, and an async requirement that gives one back.

## Example

```sable
module Example

protocol Same {
    fn same(_ other: Self) -> Bool
}

fn check(_ a: any Same, _ b: any Same) -> Bool {
    return a.same(b)
}
```

## Fix

```sable
module Example

protocol Same {
    fn same(_ other: Self) -> Bool
}

fn check<T: Same>(_ a: T, _ b: T) -> Bool {
    return a.same(b)
}
```
