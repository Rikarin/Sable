# S3237: an actor's isolated member reached without waiting

A call into an actor from outside it waits its turn: the actor runs one
call at a time (SYNTAX.md §19). Two ways of reaching a member would not
wait, and so are not allowed, as in Swift:

- meeting a protocol's requirement. Code that reaches the member through
  the protocol — a generic function's, or an existential's — does not know
  it is an actor's, and calls straight in;
- taking a method as a value from outside the actor: `counter.add` is a
  closure that may be called anywhere, later, without waiting.

A `nonisolated` member is the actor's code that reaches none of its state
but what never changes (its `let`s), and is reached from anywhere: it may
meet a requirement, and be taken as a value.

## Example

```sable
module Example

protocol Named {
    fn name() -> String
}

actor Account: Named {
    var owner = "ada"

    fn name() -> String {
        return owner
    }
}
```

## Fix

Meet the requirement with what does not change, `nonisolated`.

```sable
module Example

protocol Named {
    fn name() -> String
}

actor Account: Named {
    let owner = "ada"

    nonisolated fn name() -> String {
        return owner
    }
}
```
