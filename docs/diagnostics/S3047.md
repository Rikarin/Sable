# S3047: a type parameter used against its declared variance

A protocol's type parameter declared `out T` may only appear where values of
`T` come out (results, read-only properties); one declared `in T` only where
they go in (parameters). That is what lets a `Producer<Cat>` be used as a
`Producer<Animal>`, or a `Consumer<Animal>` as a `Consumer<Cat>`. A use in the
other position, or in an invariant one such as a mutable array or a `get set`
property, would make that substitution unsound, so it is an error.

## Example

```sable
module Example

protocol Producer<out T> {
    fn next() -> T?
    fn accept(_ value: T)
}
```

## Fix

Keep each use on the side the variance allows, split the protocol in two, or
drop the variance annotation to make the parameter invariant.

```sable
module Example

protocol Producer<out T> {
    fn next() -> T?
}

protocol Consumer<in T> {
    fn accept(_ value: T)
}
```
