# S7003: a generic function or type that needs endless copies of itself

Sable compiles a generic function once for each set of type arguments it is
used with. A generic function that calls itself — directly, or through other
functions — with a type argument built from its own, such as `(T, T)`, `T[]`
or `Box<T>`, would therefore need a copy for a larger type each time: the copy
for `Int` needs one for `(Int, Int)`, which needs one for
`((Int, Int), (Int, Int))`, and so on without end. This is called polymorphic
recursion.

Where it can, the compiler instead compiles such a function a second way,
once for every type: each type parameter stands for `any` of its
constraints, so a value is passed in a box together with what its type can
do, and the larger types the function builds are boxed the same way. That
works when each of the function's parameters, and its result, is either one
of its type parameters or mentions none of them, and each type parameter is
constrained to protocols alone. A build that compiles generic code once for
every type (`-generics=unspecialised`, docs/06 §6.2) also serves a parameter
like `T[]`, `T?`, a slice of `T`, a plain generic struct of `T` or a closure
over `T`, giving the one function the larger type's metadata at run time.
This error is what remains, in either kind of build: a type parameter
constrained to a class, which neither a box nor metadata stands in for, or
a parameter the function cannot be compiled once for.

The compiler points at the call that asks for the larger copy.

A generic type is laid out once for each set of type arguments, too, so one
that holds itself with a type argument built from its own — a union case
holding a `Tree<T?>` inside `Tree<T>`, or a struct holding an array of
`Box<(T, T)>` inside `Box<T>`, directly or through other generic types —
needs a layout for `Tree<Int>`, then `Tree<Int?>`, then `Tree<Int??>`,
without end. There is no boxed fallback for a type: the compiler points at
the type's declaration, and the fix is to hold the same type arguments.

## Example

```sable
module Example

class Animal {
    init() { }
}

final class Pack<T: Animal>: Animal {
    let leader: T
    init(leader: T) {
        self.leader = leader
        super.init()
    }
}

fn depth<T: Animal>(_ animal: T, _ n: Int) -> Int {
    if n == 0 { return 0 }
    return 1 + depth(Pack(leader: animal), n - 1)
}

fn main() { print(depth(Animal(), 3)) }
```

## Fix

Take the class itself, or a type parameter constrained to protocols alone,
so that what grows is a value of the one type; or keep what grows in a
value rather than in a type, so the recursion calls the same copy of the
function each time.

```sable
module Example

class Animal {
    init() { }
}

final class Pack<T: Animal>: Animal {
    let leader: T
    init(leader: T) {
        self.leader = leader
        super.init()
    }
}

fn depth(_ animal: Animal, _ n: Int) -> Int {
    if n == 0 { return 0 }
    return 1 + depth(Pack(leader: animal), n - 1)
}

fn main() { print(depth(Animal(), 3)) }
```

For a type, keep the arguments as they are:

```sable
module Example

union Tree<T> {
    Leaf
    Node(value: T, left: Tree<T>, right: Tree<T>)
}
```
