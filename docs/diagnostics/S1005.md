# S1005: more text after a single construct

A tool that parses a single expression, type or statement, rather than a
whole file, found text left over after it: `1 + 2 3`, say, where one
expression was asked for. The message names the first token that was not
used and what had already ended.

Compiling a file never reports this: a file is a list of declarations, and
whatever follows one is the start of the next, or a syntax error of its own.
It comes from programs built on the compiler's libraries
(`SyntaxTree.ParseExpression`, `ParseType` and `ParseStatement`), which read
one piece of code at a time.

Give the tool one construct, with nothing after it; to give several, put
them in a file.
