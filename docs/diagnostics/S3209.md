# S3209: `&` at a call marks what the call may write

`&` before an argument says the call may write it: it is required for an
argument to an `inout` or `out` parameter (an `out` one may be written
`out x` instead), and an error anywhere else, so that reading a call tells
you what it can change.

A `T&` parameter only reads the caller's storage, in place, so its
argument is written as it is: `area(bounds)`, not `area(&bounds)`. Outside
a call's arguments, `&expr` makes a reference value: `let first =
&bag.items[0]` is an `Item&`.

## Example

```sable
module Example

fn bump(_ n: inout Int) {
    n += 1
}

fn twice(_ n: Int) -> Int {
    return n * 2
}

fn run() -> Int {
    var n = 1
    bump(n)
    return twice(&n)
}
```

## Fix

```sable
module Example

fn bump(_ n: inout Int) {
    n += 1
}

fn twice(_ n: Int) -> Int {
    return n * 2
}

fn run() -> Int {
    var n = 1
    bump(&n)
    return twice(n)
}
```
