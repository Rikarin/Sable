# S3225: an `@extern` function given a pointer is `unsafe`

An `@extern` function that takes a pointer — a `RawPtr`, or a struct with one
in it, as Sable.Interop's `CStr` and `CFunction` are — is declared `unsafe fn`
(SYNTAX.md §24). Making a pointer is safe, so nothing but the caller's word
says that it points at what C reads or writes, for as long as C does: the
call is made in an `unsafe` block, which is where that word is given.

A function that only gives a pointer back need not be: using the pointer is
what is unsafe.

## Example

```sable
module Example

@extern("c", "strlen")
fn length(_ text: RawPtr<I8>) -> UInt
```

## Fix

```sable
module Example

@extern("c", "strlen")
unsafe fn length(_ text: RawPtr<I8>) -> UInt

fn lengthOfNothing() -> UInt {
    var nothing: I8 = 0
    return Memory.withPointer(to: &nothing) { (text: RawPtr<I8>) -> UInt in
        unsafe {
            return length(text)
        }
    }
}
```
