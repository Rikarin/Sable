# S3165: an associated type through `any P` with nothing to be erased to

A call of a requirement through an `any P` opens the existential: it runs
on the value as a type known only when the program runs, and what it gives
back is erased again. A result of `Self` comes back as the existential
itself (`shape.doubled()` is an `any Shape`), and a result of one of `P`'s
associated types as the existential of the protocols that associated type
is constrained to: for `associatedtype Unit: Named`, `shape.unit()` is an
`any Named`. One constrained to no protocol comes back as an `any Any`.

An associated type constrained to a generic protocol or to a class has no
such existential, since a type known only at run time cannot be checked
against it; and an error of an associated
type (`throws(Failure)`) is not erased to `any Error` through an existential
yet. Such a requirement is reached through a generic parameter, which names
one conforming type for the whole call.

## Example

```sable
module Example

protocol Maker<T> {
    fn make() -> T
}

protocol Store {
    associatedtype Item: Maker<Int>
    fn first() -> Item
}

fn peek(_ store: any Store) {
    let item = store.first()
}
```

## Fix

Constrain the associated type to the protocols its values are used through,
or reach the requirement through a generic parameter.

```sable
module Example

protocol Maker<T> {
    fn make() -> T
}

protocol Store {
    associatedtype Item: Maker<Int>
    fn first() -> Item
}

fn peek<S: Store>(_ store: S) -> S.Item {
    return store.first()
}
```
