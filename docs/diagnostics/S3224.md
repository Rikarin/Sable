# S3224: a type C does not have

What an `@extern` or `@export` function takes and gives crosses to C, so it
must be something C has the same way (SYNTAX.md §24): an integer type, `F32`,
`F64`, `Bool`, a `RawPtr` (a C pointer; so is a struct of one, as `CStr` is),
or a struct whose fields are those, which is passed as C passes the struct of
the same fields. Each is passed by value, as C passes it.

A `String` is a counted Sable object, not a C string: `withCString`
(Sable.Interop) lends it as one. A class, an optional,
an array or a closure has no C counterpart either; a struct with a `deinit`
would be copied by C without it ever running.

The same holds for an `@export` variable's type. C's `...` is written
`_ args: CVarArg...`, last, after at least one fixed parameter, and only on
an `@extern` function: C calls an exported one with its parameters fixed.

## Example

```sable
module Example

@extern("c", "puts")
fn puts(_ text: String) -> I32
```

## Fix

Pass what C has: here, the number the C function works on.

```sable
module Example

@extern("c", "abs")
fn cAbs(_ x: I32) -> I32
```
