# S3235: an `async let` read from a closure

An `async let` starts a child task that belongs to the scope declaring it:
the scope waits for it, and cancels it if it was never read, before it ends.
A closure may run anywhere and at any time — after that scope has ended, or
in another task — so it cannot read the `async let` itself. The child of
another `async let` is such a closure too.

## Example

```sable
module Example

async fn price() -> Int { return 3 }

async fn total() -> Int {
    async let p = price()
    let later = Task.spawn { await p * 2 }
    return await later.value
}
```

## Fix

Read the `async let` where it is declared, and capture the value.

```sable
module Example

async fn price() -> Int { return 3 }

async fn total() -> Int {
    async let p = price()
    let value = await p
    let later = Task.spawn { value * 2 }
    return await later.value
}
```
