# S3143: a subclass initialiser that does not call `super.init`

A subclass's object is its superclass's too, and only the superclass's own
initialiser builds that part of it: its stored fields. So an initialiser of a
subclass calls `super.init(…)` on every path that returns, or hands the work
to another initialiser with `self.init(…)`. Left out, the superclass's fields
would hold nothing at all.

One exception: a superclass made with the implicit `init()` — it declares no
initialiser, and every field it has starts with a value — has that called for
an initialiser that never calls `super.init` itself.

## Example

```sable
module Example

open class Creature {
    var name: String
    init(name: String) { self.name = name }
}

class Goblin: Creature {
    var rage: Int
    init() {
        self.rage = 0
    }
}
```

## Fix

Call the superclass's initialiser once the subclass's own fields are set.

```sable
module Example

open class Creature {
    var name: String
    init(name: String) { self.name = name }
}

class Goblin: Creature {
    var rage: Int
    init() {
        self.rage = 0
        super.init(name: "goblin")
    }
}
```
