# S3073: a value that is not Sendable crosses an actor's boundary

What goes into an actor — the arguments of a call to it — and what comes
back out — its results, the properties read from it — crosses an isolation
boundary, and must be `Sendable`: safe for the actor's code and the
caller's to hold at once.

A type is Sendable by what it is made of: numbers, strings and the other
built-in values are; a struct, union, tuple, optional or array is when
everything it holds is; an actor is. A class is shared mutable state, and
is not — unless it is `@immutable` or `@MainActor`. A closure may capture
such state, and is not. A type parameter is when it is constrained
`T: Sendable`.

## Example

```sable
module Example

class Tally {
    var count: Int = 0
}

actor Ledger {
    fn record(_ tally: Tally) -> Int {
        return tally.count
    }
}

@main
async fn main() {
    let ledger = Ledger()
    print(await ledger.record(Tally()))
}
```

## Fix

Send a value instead — here, a struct holding what the actor needs.

```sable
module Example

struct Tally {
    var count: Int
}

actor Ledger {
    fn record(_ tally: Tally) -> Int {
        return tally.count
    }
}

@main
async fn main() {
    let ledger = Ledger()
    print(await ledger.record(Tally(count: 0)))
}
```
