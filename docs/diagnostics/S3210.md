# S3210: an override or a conformance adds `@escaping`

A closure parameter that is not `@escaping` lends its closure only for the
length of the call: the caller may give one that captured a local, or a
reference into a region, which dies when the call is over. A method that
overrides one, or meets a protocol's requirement, is called through the
original — by code that knows only what the base method or the requirement
says — so it may not keep what the original only borrows.

Taking `@escaping` off is always allowed: a member that keeps less than
it may meets the promise. Putting it on is not; put it on the base method
or the requirement as well, if every member of it may keep the closure, or
keep a copy of what the closure computes instead of the closure.

The same holds of a function type: `(@escaping () -> Int) -> ()` is a
function that may keep the closure it is given, and a value of it does not
fit where a `(() -> Int) -> ()` is wanted (S3004); the other way round it
does.

## Example

```sable
module Example

protocol Runner {
    fn run(_ action: () -> Int) -> Int
}

final class Keeper: Runner {
    var kept: (() -> Int)? = none

    fn run(_ action: @escaping () -> Int) -> Int {
        kept = action
        return action()
    }
}
```
