# S3484: a generator that throws

A generator's body runs inside its iterator's `next()`, as each element is
asked for (SYNTAX.md §5, "Generators"), so an error it threw would come out of
`next()` — and `Iterator`'s `next()`, which every `for` loop and every generic
algorithm calls, does not throw. A generator cannot be `throws`: what its body
calls that throws, it handles there.

## Example

```sable
module Example

union ParseError: Error {
    NotANumber
}

fn number(_ text: String) throws -> Int {
    if text.isEmpty {
        throw ParseError.NotANumber
    }
    return text.count
}

fn numbers(_ texts: String[]) throws -> some Sequence<Int> {
    for text in texts {
        yield try number(text)
    }
}
```

## Fix

Catch the error in the body, and decide there what it means for the
sequence — skip the element, or end:

```sable
module Example

union ParseError: Error {
    NotANumber
}

fn number(_ text: String) throws -> Int {
    if text.isEmpty {
        throw ParseError.NotANumber
    }
    return text.count
}

fn numbers(_ texts: String[]) -> some Sequence<Int> {
    for text in texts {
        if let n = try? number(text) {
            yield n
        }
    }
}
```
