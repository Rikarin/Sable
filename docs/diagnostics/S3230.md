# S3230: a generator breaks a rule

A source generator (docs/08) must give the same output for the same input on
every machine, so it is held to the rules of docs/08 §8.5. This error says
which rule a generator breaks, at the line in its `generators/` file:

- It imports a module other than `Sable.Generators`, `Sable.Text`,
  `Sable.Collections`, `Sable.Math` and the generator program's own modules.
- It uses something that reads, writes or waits: `Runtime`, `print`, `Task`
  or `Region`.
- It has conditional compilation (`#if`).
- Its signature is not
  `fn name(_ declaration: Declaration, into output: inout Output)`, or
  `fn name(_ pkg: Package, into output: inout Output)` for a generator given
  the whole package. `always: true` is only for the second kind.
- Its name in `@generator("name")` is not a string literal, is one of the
  compiler's own attributes (`derive`, `inline`, `test`, and the others in
  SYNTAX.md §22), or is the name of another generator that the same package
  can see.

A generator that needs data from outside the program, such as a file, a
tool or the environment, is a build script instead (docs/05 §5.6).

A generator that breaks this rule

```text
@generator("json")
fn json(_ declaration: Declaration, into output: inout Output) {
    print("generating \(declaration.name)")   // S3230: no output but `output`
}
```

is fixed by reporting through `output`, which the compiler shows at the
attribute:

```text
@generator("json")
fn json(_ declaration: Declaration, into output: inout Output) {
    output.warning("generating \(declaration.name)")
}
```
