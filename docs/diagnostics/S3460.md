# S3460: classes that hold one another strongly

This is a warning. Two or more classes hold one another through strong
references, so objects linked that way keep each other alive: once the last
reference from outside goes, their counts never reach zero and they are never
freed (docs/02 §2.2). The warning prints the way round, field by field.

The check looks at types, not objects: it cannot know whether a program
ever links objects into a cycle, and it does not look through protocols,
closures or type parameters. A class that holds its own kind — a list's
`next` — is not reported.

## Example

```sable
module Example

class Parent {
    var children: Child[>..] = []
}

class Child {
    var parent: Parent?
}
```

## Fix

Make the reference that points back up `weak` (it reads as none once the
object is gone) or `unowned` (it traps if read after):

```sable
module Example

class Parent {
    var children: Child[>..] = []
}

class Child {
    weak var parent: Parent?
}
```
