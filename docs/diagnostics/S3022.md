# S3022: a type argument that cannot be inferred

A generic function's type parameters are inferred from the arguments of the
call and from the type its result is expected to have. When a type parameter
appears in neither, there is nothing to infer it from. Nor is there when the
argument is a literal that takes its type from where it is: `[]` alone is no
particular array, and `none` no particular optional, nor does a closure that
only gives one say what its result is of. The same is so of a generic union's
case: `Res.Ok(xs: [])` says nothing of `Res`'s parameter, nor does a case that
carries nothing, and `Res<Int>.Ok(xs: [])` does.

## Example

```sable
module Example

fn zero<T>() -> Int { return 0 }

fn start() -> Int {
    return zero()
}
```

## Fix

Use the type parameter in a parameter or the return type, or drop it. For a
literal, say what it is of: `let xs: Int[>..] = []`, or `let x: Int? = none`,
and pass that. For a closure, write its type: `{ () -> Int? in none }`.

```sable
module Example

fn zero() -> Int { return 0 }

fn start() -> Int {
    return zero()
}
```
