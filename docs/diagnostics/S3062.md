# S3062: overlapping accesses in one call

The law of exclusivity: while a call changes a piece of storage (through an
`inout` argument, or as the receiver of a `mutating` method), nothing else
in that call may read or change the same storage. Two `inout` arguments that
name the same variable, field or element, or an `inout` argument and a `T&`
argument to the same place, would see each other's writes in an order that
depends on the callee. When the compiler can see the overlap it is this
error; where it cannot (through classes, say) it is checked at run time.

## Example

```sable
module Example

fn bump(_ x: inout Int, _ y: inout Int) {
    x = x + 1
    y = y + 2
}

@main
fn main() {
    var n = 0
    bump(&n, &n)
    print(n)
}
```

## Fix

Pass storage that does not overlap, or copy one side into a local first and
write it back afterwards.

```sable
module Example

fn bump(_ x: inout Int, _ y: inout Int) {
    x = x + 1
    y = y + 2
}

@main
fn main() {
    var n = 0
    var m = n
    bump(&n, &m)
    print(n + m)
}
```
