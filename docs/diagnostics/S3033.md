# S3033: an error with nowhere to go

A `throw`, or a `try` that passes an error on, sits in a function that does
not declare `throws`. Errors in Sable are checked: each one must either be
declared in the signature or handled where it occurs. A closure counts as its
own function, so a `try` inside it cannot use the enclosing function's
`throws`.

The catches of a `do` are tried in order, and an error none of them matches
leaves the `do` as if thrown from there. So a `do` whose catches do not cover
every error its body throws — `catch .NotFound` alone, when `.Denied` can be
thrown too, or only catches with a `where` guard — needs somewhere for the
rest to go as well.

## Example

```sable
module Example

union ParseError { Empty }

fn parse(_ s: String) throws(ParseError) -> Int { return 0 }

fn read() -> Int {
    return try parse("1")
}
```

## Fix

Declare `throws`, use `try?`, or supply a fallback with `catch`.

```sable
module Example

union ParseError { Empty }

fn parse(_ s: String) throws(ParseError) -> Int { return 0 }

fn read() -> Int {
    return try parse("1") catch { 0 }
}
```
