# S3470: an unsafe function used outside unsafe code

The function is declared `unsafe fn`: it is safe only when its caller keeps a
promise the compiler cannot check, which its documentation states — that the
bytes are well-formed UTF-8, that a pointer points into what it was allocated
for (SYNTAX.md §23). A call to it, or taking it as a value that could be
called anywhere, is allowed only where the code says it keeps that promise:
inside an `unsafe { }` block, or in the body of another `unsafe fn` (a
closure's within either included).

## Example

```sable
module Example

unsafe fn rawValue(_ n: Int) -> Int {
    return n
}

fn caller() -> Int {
    return rawValue(1)
}
```

## Fix

Check what the function's documentation asks, then say so with an `unsafe`
block around the call — or call the safe function beside it, if there is one
(`String.fromUtf8` validates where `String.fromUtf8Unchecked` does not). A
function that only passes the promise on to its own callers can be an
`unsafe fn` itself.

```sable
module Example

unsafe fn rawValue(_ n: Int) -> Int {
    return n
}

fn caller() -> Int {
    unsafe {
        return rawValue(1)
    }
}
```
