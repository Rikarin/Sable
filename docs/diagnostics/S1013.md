# S1013: `ref` and `borrowing` are written `T&`

Sable has one reference type, `T&`, written after the type as `T?` and
`T[]` are. A parameter that refers to its argument says so in its type,
`a: Node&`, and so does a result that is a reference, `-> Node&`. Whether
a reference rooted in a parameter may be returned is not written either:
root inference decides it from the body and the result type.

`ref T`, `ref a: T` and `borrowing h: T` are not Sable. The words are
reserved so that code written in either spelling is told so; it is read as
the reference it meant, and the fix writes it.

Classes and `@noncopy` values are passed by reference without writing
anything, so a `borrowing` parameter of one can usually just drop the word.

## Example

```sable
module Example

struct Node {
    var value: Int
}

fn pick(ref a: Node, ref b: Node) -> ref Node {
    return a.value >= b.value ? a : b
}
```

## Fix

```sable
module Example

struct Node {
    var value: Int
}

fn pick(_ a: Node&, _ b: Node&) -> Node& {
    return a.value >= b.value ? a : b
}
```
