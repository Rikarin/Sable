# S3223: an @extern or @export that cannot be

`@extern("c", "name")` declares a C function a program calls, and
`@export("c", "name")` gives a Sable function a name C calls it by
(SYNTAX.md §24). `@extern("c")` alone takes the C name to be the function's;
`@export("name")` alone takes the language to be C. The names are string
literals, and the C name is one C can give a function.

Either is a function of the module — C has no methods, and no local
functions — that is not generic,
does not wait and does not throw: C has none of those. An `@extern` function
has no body, since the C library's is its body; an `@export` function has
one, since it is what C calls. A function is one or the other, once.

`@export` on a variable names its storage for C: the variable is one of the
module's (not a type's `static var`) and stored, not computed or `lazy`.

## Example

```sable
module Example

@extern("c", "abs")
fn cAbs(_ x: I32) -> I32 {
    return x < 0 ? -x : x
}
```

## Fix

```sable
module Example

@extern("c", "abs")
fn cAbs(_ x: I32) -> I32
```
