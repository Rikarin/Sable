# S3515: an `@autoclosure` parameter that cannot take one

`@autoclosure` makes the argument written at a call the body of a closure
that takes nothing and gives the argument's value, worked out only when the
callee calls it. So the parameter is a `() -> T`, and the call writes a `T`.
It is refused on a parameter:

- of any other type: `n: @autoclosure Int` is written `n: @autoclosure () -> Int`;
- whose function type takes parameters, as the closure is called with none;
- whose function type is `async`: the callee works the value out where it
  asks for it, without waiting;
- that is variadic, as each argument would be a closure of its own;
- that is `inout`, `out` or `consuming`: the closure is made at the call,
  a value, not the caller's storage.

## Example

```sable
module Example

fn orElse(_ value: Int?, _ fallback: @autoclosure Int) -> Int {
    if let v = value {
        return v
    }
    return fallback
}
```

## Fix

```sable
module Example

fn orElse(_ value: Int?, _ fallback: @autoclosure () -> Int) -> Int {
    if let v = value {
        return v
    }
    return fallback()
}
```
