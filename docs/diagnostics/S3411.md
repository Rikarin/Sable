# S3411: globals whose initial values need each other

A program's globals and types' static stored properties are given their
initial values before `main` runs, each after the ones it reads, in
whichever file they are declared: what its initial value names, and what
the functions it calls read. Two that need each other, directly or
through other globals and functions, have no order that works: whichever
is set first would read the other before it has a value. One that needs
itself is the same mistake.

Calls through a protocol or a closure value are not followed, as only
running them says where they go.

## Example

```sable
module Example

let width: Int = area / height
let height: Int = 4
let area: Int = width * height

fn main() {
    print(width)
}
```

## Fix

Give one of them a value that does not depend on the other.

```sable
module Example

let width: Int = 3
let height: Int = 4
let area: Int = width * height

fn main() {
    print(area)
}
```
