# S3164: a function opened with a Type that is not compiled once

A call that opens a `Type` runs the generic function compiled once for
every type, given the type's metadata in place of its type parameter (docs/06
§6.2). A generic function is compiled so only when everything its body does
with its type parameters is something such code can do; the rest — a
method of a generic class a subclass may override, and the other cases docs/06
lists — is copied for each type it is called with, which needs the type known where
the call is compiled. The message says what in the body kept it so.

This is reported when the program is lowered, in a specialised build as in
an unspecialised one.

## Example

```sable
module Example

protocol Zero {
    static fn zero() -> Self
    fn name() -> String
}

open class Holder<T> {
    let item: T

    init(_ item: T) {
        self.item = item
    }

    open fn get() -> T { return item }
}

fn show<T: Zero>(_ type: T.Type) -> String {
    return Holder(T.zero()).get().name()
}

fn describe(_ t: Type) -> String {
    return show(t)
}
```

## Fix

Use only what code compiled once can do with the type: here, a value of `T`
itself, not a class a subclass may override the methods of.

```sable
module Example

protocol Zero {
    static fn zero() -> Self
    fn name() -> String
}

fn show<T: Zero>(_ type: T.Type) -> String {
    return T.zero().name()
}

fn describe(_ t: Type) -> String {
    return show(t)
}
```
