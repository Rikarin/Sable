# S3239: a core module of the standard library imports an extension

The standard library's modules come in two tiers, listed in
`lib/package.sb` (docs/06 §6.4): the core (`Sable.Core`, `Sable.IO`,
`Sable.Diagnostics`, `Sable.Testing`...) and the extensions built on it
(`Sable.DependencyInjection`, `Sable.Hosting`, `Sable.Configuration`...). A
core module never imports an extension one, so the core stands on its own:
what a program that uses no extension compiles and links. An extension may
import any module.

Only the standard library's modules, named `Sable.*`, have a tier; a
program's modules may import any.

## Example

```sable
module Sable.Diagnostics

import Sable.DependencyInjection
```

## Fix

Move what needs the extension into it, which imports the core module in
turn: a conformance may live in the protocol's module as well as the type's,
as `Logger.Of`'s to `Injectable` does in Sable.DependencyInjection.

```sable
module Sable.DependencyInjection

import Sable.Diagnostics
```
