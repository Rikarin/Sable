# S3067: a move-only type for a generic parameter that copies

Every generic parameter is implicitly `Copyable`: the generic code may copy
a value of it, as `two` below does. A `@noncopy` type cannot be copied, so it
cannot stand for such a parameter. The error is reported where the type is
given — at the call, or where the generic type is named — rather than inside
the generic code once it is made for that type.

A generic parameter written `T: ~Copyable` may stand for a move-only type;
its code then moves values of `T` rather than copying them.

## Example

```sable
module Example

@noncopy struct Token { var id: Int }

struct Pair<T> {
    var first: T
    var second: T
}

fn two<T>(_ x: T) -> Pair<T> {
    return Pair(first: x, second: x)
}

@main
fn main() {
    let pair = two(Token(id: 1))
    print(pair.first.id)
}
```

## Fix

A move-only value can only be in one place: take it with a parameter that
allows one, and move it.

```sable
module Example

@noncopy struct Token { var id: Int }

struct Holder<T: ~Copyable> {
    var item: T
}

fn hold<T: ~Copyable>(_ x: consuming T) -> Holder<T> {
    return Holder(item: x)
}

@main
fn main() {
    let held = hold(Token(id: 1))
    print(held.item.id)
}
```
