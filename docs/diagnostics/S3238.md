# S3238: an actor's state in a closure run on another thread

`Task.blocking`'s closure, and any other passed to a `@Sendable` parameter
that cannot wait (it is not `async`), runs on another thread, alongside the
code that wrote it. It cannot wait for an actor's turn, so it may not read
an actor's `var`s or call its isolated methods — not even an actor whose
own method wrote the closure: by the time it runs, the actor is another
task's. An async closure may: it hops onto the actor, and back.

## Example

```sable
module Example

actor Log {
    var lines: String[>..] = []

    fn save() async -> Int {
        return await Task.blocking { lines.count }
    }
}
```

## Fix

Read what the closure needs first, on the actor, and give it the value.

```sable
module Example

actor Log {
    var lines: String[>..] = []

    fn save() async -> Int {
        let count = lines.count
        return await Task.blocking { count }
    }
}
```
