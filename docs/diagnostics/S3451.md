# S3451: what the runtime profile leaves out

The program is built with a smaller runtime profile — `--runtime minimal`,
or `runtime = "minimal"` in the manifest's `[targets.<triple>]` — and its own
code uses a part of the runtime that profile does not link (docs/06 §6.1):

- an `import` of a module that needs the executor, threads or the system
  (`Sable.Concurrency`, `Sable.IO`, `Sable.Net`, `Sable.Process`,
  `Sable.IO.Ipc`, `Sable.IO.Ports`, `Sable.Interop`, `Sable.Crypto.X509`),
  or that imports one of them;
- `async` code — an `async fn`, an `async` closure, `async let` — which runs
  on the runtime's executor.

The minimal profile is the core alone: one thread, no task, no files or
sockets. A smaller runtime is what such a build promises, so the compiler
refuses the use rather than linking what it costs. What the standard library
reaches of a part left out without the program asking for it plainly traps
when it is called, naming the runtime function.

Either remove the use, or build with a profile that has it: `--runtime
standard`, or the full runtime, the default.
